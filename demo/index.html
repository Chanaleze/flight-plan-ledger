How this demo works

  • Hashing happens twice: once in your browser (a tested byte-exact mirror of the Python canonicalization) and once on the server with the real code — the badge in step 1 proves they agree.
  • The server is stateless: one serverless function runs the actual ledger modules (canonicalize, Ed25519, chain check, recovery). Your chain is sent with each request; nothing is stored server-side.
  • Keys are throwaway: each signature uses a fresh keypair whose private half is discarded immediately. Demo entries are stamped org:demo.
  • This is a resilience sidecar prototype, not an ATC system. It decides nothing and controls nothing — it only remembers and proves.
